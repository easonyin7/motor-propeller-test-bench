# CV MVP：USB 相机基础验证

依据项目聊天“自动化测试评估”，最终 CV MVP 为 USB 相机 → ROI → LCD/LED 数字识别 → 有效性检查 → CSV。本目录提供相机、人脸、手势、模拟数码管测试，以及当前实物 LED/LCD 仪表的标定识别。

## 实物仪表识别（2026-10-17）

双击 `start_instruments.cmd`，读取当前摆放的上方四位红色数码管，以及下方绿色液晶表的电压 V、电流 A、功率 W、电能 Wh。商家确认相机不能调焦，因此保持现有位置和镜头设置，通过原始1080P画面中的屏幕区域进行识别。放大预览仅便于查看，不会增加镜头实际拍到的细节。

程序分别寻找红色显示窗的暗色边界、绿色LCD的屏幕边界，对两块屏幕独立做透视校正；LCD再利用静态边缘和V/A/W单位区域做局部对齐，排除会变化的数字和Wh辅助单位。这样仪表相对桌面的小范围移动不会再被整幅场景的特征匹配拦住。红色LED提取发光笔画，绿色LCD提取暗色笔画，分别读取七段数字和实际可见的小数点。至少3次有效读数、持续0.6秒一致后，各字段独立发布稳定值；改变或无效时立即清空该字段，不沿用旧读数。单位区域与标定照片不一致时暂停该字段，避免把切换页面的辅助读数继续当作Wh。单位检查是图像相似性门槛，尚未验证所有可能的显示页面。

2026-10-18 晚补充：电机运行时，拉力LED仍有约一半的采样帧因数码管复用刷新而缺笔画；逐帧记录显示相机画面、曝光和字段时效正常，缺笔画集中出现在前导零的同一段码。离线把阈值放宽后，静止的“0005”会被读成“0004/0006”，因此没有采用降阈值方案。现在每一帧都单独扫描LED（约6毫秒），缓存最近一次完整读数；发布样本的当前帧不完整时，最多沿用0.25秒内的完整读数。沿用值是真实完整的单帧识别结果，不拼接不同帧的笔画，也不改变0.6秒一致判定；状态中新增 `led_scan_readable_fraction` 和 `led_cache_hits` 便于核对。LCD仍按原0.2秒周期读取。

当前配置 `instrument_config.json` 对应 `calibration/instrument_20261017_163432/frame.png`。上方保留四位前导零，单位待确认；LCD按当前三个数字槽位标定，小数点位置依据图像检测。电压、电流和功率目前要求确认小数点，若仪表量程变化后出现无小数点、更多位数、负号或新的布局，会暂停或需要重新标定。每块屏幕搜索标定位置周边约180个原始像素，并检查面积和形状；这是定位限制，不表示范围内所有位置都已实测。已通过两块屏幕各自平移约90像素、转动2度的回放，以及用户实际小范围移动、停住后恢复读数的验证。明显改变距离、大幅旋转、超出搜索范围、更换仪表或布局后仍需重新标定。

每次测试写入 `instrument_logs/时间戳/`：`samples.csv` 为各字段即时值、稳定值、单位、有效标记和拒绝原因，`changes.csv` 为各字段稳定值变化，`manual_reviews.jsonl` 为人工核对，`summary.json` 为退出汇总。每次另存当次配置；`instrument_logs/latest.json` 为当前状态。默认不保存连续照片或录像，不上传图像；仅标定和按需诊断保存本地照片。采集与识别在后台执行，窗口显示整体画面与两块屏幕放大图。

验证记录见 `INSTRUMENT_TEST_20261017.md`。`verify_instruments.py` 的11项检查覆盖两张已标注实拍照片、整体和单独屏幕移动、亮度变化，以及电压小数点消失、Wh单位被遮挡和黑帧拒绝。这不是全数字、全量程准确率测试。此前HTML数码管测试仍由 `start_digits.cmd` 独立启动。

## 两组数字测试

双击 `start_digits.cmd` 打开数字识别窗口。使用 **1920×1080** 相机原始画面中的数字区域进行识别；预览缩到960像素宽，数字不镜像。采集、识别在后台，窗口只显示最新画面。

当前校准针对用户提供的随机数码管 HTML：每行固定三个整数槽位加一个小数槽位，前导空白右对齐，范围0.0～100.0，每10秒刷新。程序只读取相机画面；HTML源代码用于了解位数、几何结构和刷新间隔，不作为读数来源。按点亮段码识别0～9，单独检测小数点，将连续至少0.6秒且至少3个有效样本的一致读数发布为稳定值；不确定时立即清空稳定值，不沿用上一轮数值。

当前画面位置已校准于 `digit_config.json`。常亮小数点作为位置锚点，允许小范围平移修正；不能补偿大幅移动、缩放或旋转。请保持相机距离与角度固定。更换场景后需要重新标定四个槽位；框选时须包含左侧空白槽位和小数点，不能仅圈当前点亮的几个字符。

窗口显示即时值、稳定值、有效样本数和变化间隔。可以点击“本次两组都正确”或“本次有读错”记录人工核对结果，尽量避开刷新瞬间。自动有效率只是能解码的样本比例，不是识别正确率。

每次测试在 `digit_logs/时间戳/` 保存：

- `samples.csv`：约5次/秒的即时值、稳定值、有效标记、采集时间与耗时。
- `changes.csv`：两组值均稳定且与上次不同的变化记录和间隔。
- `manual_reviews.jsonl`：用户点击按钮留下的人工核对记录。
- `summary.json`：退出时的汇总；实时状态为 `digit_logs/latest.json`。

Windows 读者短暂占用状态JSON时，程序会重试替换；实时状态写入暂时失败不会中断识别，CSV继续记录。该行为由 `verify_status_lock.py` 使用真实Windows文件锁验证。

数字阶段为标定保存了两张本地校准图，位于 `calibration/`，不保存连续录像。`capture_sample.py` 可以采集单张图；运行中的数字程序收到 `calibration/request_frame` 文件时可保存一张 `live_sample.png` 供诊断。所有处理在本机完成。

本次结果见 `DIGIT_TEST_20261013.md`。这次验证不能替代实物仪表的反光、曝光、刷新闪烁、震动及真实标注准确率测试。

## 现在使用

双击 `start.cmd` 打开中文实时窗口。默认按名称选择 **2MP USB Camera**，不会自动改用内置相机。人脸框、手部骨架和英文类别叠加在画面上，中文结果、置信度和性能指标在下方显示。镜像只影响预览方向，可关闭。

依次测试：

1. 正面对准镜头，确认出现人脸框；轻微左右转头观察跟随情况。
2. 手掌完整进入画面，依次张开手掌、握拳、点赞、V 手势，每个保持 2–3 秒。
3. 可追加食指向上、拇指向下、“我爱你”（拇指、食指、小指伸出）。
4. 手移出画面、脸移出画面，确认对应检测数回到 0。
5. 点击“停止测试并退出”或按 Esc，释放相机并生成汇总。

请观察标签是否与真实动作相符，以及有没有明显延迟、跳变、漏检。所有检测计数都是模型输出，不是准确率；没有人工标注，不能据此计算识别正确率。无手时不应出现手势，低于 0.65 的手势输出显示“未分类”。

“人脸”目前指检测脸部位置和置信度，不含注册、身份比对或人员识别。人脸采用近距离模型，远距离、小脸、侧脸、遮挡或背光可能降低效果。本测试成功不能直接证明 LCD/LED OCR 可用。

## 参数与结果

PowerShell 在项目根目录执行：

```powershell
.\cv_mvp\run.ps1 -Action cameras
.\cv_mvp\run.ps1 -Action probe -Seconds 12
.\cv_mvp\run.ps1 -Action run -Width 1920 -Height 1080
```

默认请求 1280×720、MJPG、30 帧/秒；窗口和日志显示实际返回分辨率。模型输入缩到不超过 960 像素宽，原始取流分辨率保留。采集线程持续读帧，推理读取最新帧，避免应用内不断累积帧队列。驱动自身延迟未单独测量。

每次测试写入 `logs/时间戳/metrics.csv`、`summary.json`，当前状态写入 `logs/latest.json`。CSV 每秒最多记录 5 次，汇总检测计数按实际推理帧累计。采集帧率为本次累计平均，处理帧率为最近约 60 次处理结果的平均；推理时间为人脸和手势两模型总耗时；画面年龄从应用收帧到推理完成，不包含设备曝光及USB/驱动的全部延迟。平均推理耗时使用最近 300 帧。

画面只在本机处理、显示，不保存照片或录像，不上传图像。后续仪表阶段可以另加可控的原始录像功能。

窗口操作、采集、推理分别处理。推理与预览缩放在后台线程，界面只接收最新画面，约每 33 毫秒尝试刷新，减少拖动窗口时卡顿。`logs/gui.json` 记录实际预览帧率和界面存活状态。采集帧率、模型处理帧率与预览帧率是不同指标。

若打开失败，请关闭 Windows 相机、会议软件等占用相机的应用。拔出相机会中止测试并提示错误。再次启动需重新连接设备。不要同时打开多个测试窗口。

若出现黑屏，程序会根据实际像素亮度提示“相机返回近黑画面”。这可能是遮挡、光线不足或设备取流异常。请先退出窗口，再将 USB 相机拔出、等待 5 秒后插回，重新启动。`mean_pixel_brightness` 在状态日志中记录平均像素亮度（0–255），用于区分取流黑屏与正常画面。可使用 `diagnose_camera.py` 比较不同采集接口的帧率、曝光和亮度，它不保存图像；`--auto-exposure` 会尝试恢复自动曝光。

## 重建环境

当前 `.venv` 已安装。若移动文件夹或重建，使用 Python 3.12：

```powershell
python -m venv cv_mvp/.venv
cv_mvp/.venv/Scripts/python.exe -m pip install -r cv_mvp/requirements.txt
```
