# 电机桨叶测试台 · 上位机 0.1

第一版本地Windows桌面软件，适配当前PX4 Motor 1和USB摄像头读表测试台。复用已经实测的执行器控制、相机识别、有限命令租约与保护程序。

现场使用请先阅读 [上位机操作指南](上位机操作指南.md)，包含完整操作步骤、补点与续测、数据导出及常见问题处理。

## 启动

双击项目根目录的 **启动上位机.cmd**。启动后默认是“历史回放”，不会连接飞控、打开摄像头或发送电机控制指令。

开发目录使用项目现有`cv_mvp/.venv`环境及`px4_mvp/.deps`依赖，不修改系统Python。2026-10-20新增Windows x64离线文件夹交付包，优先使用随包的`runtime/`；接收方无需安装Python或Codex。发布包使用说明见根目录`DELIVERY_README.md`，交付步骤见`distribution/`。交付形式为解压后运行的文件夹包，并非单文件EXE或安装器。

## 先体验历史回放

1. 在左侧选择“低输出验证”“中段曲线”“高段曲线”或“全部已测档位”。也可以输入并加入任意自定义档位（0.010～1.000，最多三位小数），或移除已有档位；预置列表只作为快捷选项。
2. 点击“开始历史回放”。实时监控会播放以前采集的读数和已保存的仪表照片，测试曲线逐点生成。
3. “历史记录”载入现有28条汇总记录，保留0.060重复点，并可打开各点的原始运行目录。
4. 停止按钮或Esc可停止回放。回放结果标记为“历史回放”，不当作新实测。

## 实机运行

1. 选择“实机测试”，刷新并选择PX4串口，确认当前相机标定。更换机位、镜头、显示仪表或曝光设置后，先重新标定和验证；此界面只能载入现有标定文件，暂未内置鼠标标定工具。
2. 选择“主测 10–100% + 自动补8点”：先执行0.10、0.20、…、0.90、1.00共10档，随后自动按本轮主测生成300～500g内部8个补点并执行，整轮正常完成后共18个测点。该预置会自动勾选“主测后自动补测300–500g（8点）”。所有档位保持10秒，单档缓升与保持合计不超过20秒；100%档位此前尚未完成实机验收，开始前需核对当前设备允许范围。其他预置和自定义方案仍可单独运行；手动加入/移除档位会取消自动补点。
3. 点击“设备预检”。它只检查飞控、零输出、相机、近零基线及数据时效，不转电机。零载基线要求至少4次一致读数、跨度不少于0.6秒、最长间隔不超过1.8秒；拉力允许2克以内的静止跳动，其他读数必须完全一致。LED刷新造成的短暂缺笔画帧会被跳过而不是判为数值变化，出现数值冲突则重新确认。预检失败时会显示各字段的读数有效率并说明未发送电机指令。
4. 连续测试时，第一档之前仍要求严格近零基线。第一档完成并停机后，后续档位、自动重测和续测**不再设置残余拉力上限**：停机后无论拉力表显示多大，只要该读数有效，就按稳定处理；读数允许在窗口内变化。电压、电流、功率仍必须归零且完全一致。残余策略同时作用于该档启动前的设置基线（不只是开始档位前的停机基线），因此不会出现“启动基线拒绝3克残余、档位还没开始就超时”的情况。实际残余值写入该档 `result.json` 的 `stopped_baselines` 和设置基线策略，不进入目标测量窗口，也不做扣零或补偿。
5. 点击“开始实机测试”，核对弹窗列出的档位与缓升/保持时间。三个现场检查项默认均不勾选，确认后才执行本轮冻结的方案。
6. 软件逐档运行并停机，默认档间等待5秒。只有“有效读数不足10个”这种统计样本不足会触发本档自动重测一次：电机已停机、输出回零后等待档间时长，再单独重测同一档位，成功后继续后续档位。执行故障、停止回执不明、输出异常、相机不可读或界面心跳失效不会自动重测，会停止后续档位。若重测后样本仍不足，方案同样暂停。
7. 结束后点击“确认现场已停转”。软件收到ACK和输出回零，不等同于已经观察到桨叶停转。

## 300–500g 补点与拉力–功率曲线

自动流程只使用本轮10个有效主测点：要求拉力随输出严格增加且覆盖300～500g，插值产生8个内部目标的油门（三位小数，不含两端），在主测停机检查通过及档间等待后自动运行，无需中间再次点击开始。开始时的现场确认同时包含自动补点规则；补点不会超过已测输出范围。主测故障、覆盖不足、非单调或无法得到8个不同指令时停止后续流程并保留已有数据，不会提高输出寻找区间。

精确补点指令保存为`session.json`中的`supplement`和`supplement_plan.json`；主测与补点用独立阶段编号记录，即使油门相同也保留两点，CSV增加`phase`和`stage_number`。续测使用已保存的补点，不重新插值，也不会把已完成主测的同油门点误当补点完成。

仍可点击左侧 **“按300–500g补8点”** 手动生成独立方案：读取本轮或最近含点的实机会话，替换当前列表但不启动电机；启动时再次确认。这个按钮与主方案中的自动补点不同。

补点属于接续前一轮运行，界面会自动勾选 **“首档接续前一轮（忽略残余拉力）”**：补点方案第一档的设置基线也允许任意残余拉力；电压、电流、功率仍必须归零。每次开始前仍要重新完成三项现场确认。若不希望首档忽略残余拉力，可取消该勾选。

“测试曲线”页新增 **拉力–功率曲线**（横轴为拉力 g，纵轴为输入功率 W），与原有四条以油门为横轴的曲线并列显示；历史参考和本轮点都按拉力排序绘制。导出和 `curves.png` 同样包含该图。

## 中止后从失败档继续

保护中止后，先完成“确认现场已停转”，再点击状态栏的 **“从失败档继续”**。软件按原方案找到第一个未完成的档位，保留已完成的点和全部原始目录，只把剩余档位列入续测方案；启动前仍会弹出三项现场确认。重启上位机后也可使用：按钮会载入最近一次“实机测试”且已确认停转的会话，不会载入历史回放或预检会话。

续测不会改变原方案、跳过档位或自动提高目标。续测的第一档发生在一次电机运行之后，因此同样使用“任意残余拉力”策略；其后的档位和自动重测继续使用该策略。若续测再次中止，可再次确认现场停转后继续，目录追加 `_resume1`、`_resume2` 等后缀，原有失败目录和日志均保留。若某档是统计样本不足而暂停，该不足点会从本轮汇总表和曲线中移出，但原始目录仍记录在 `report.md` 的“从失败档续测记录”中。

“停止测试”通过当前控制进程的取消通道请求撤销输出，并阻止后续档位。界面卡死或USB断开时，有限命令租约仍由原执行层限制，但软件停止按钮不能替代现场独立切断电调动力电源。

实机执行还检查由界面主事件循环每0.25秒刷新的独立心跳；超过2秒或时间无效即中止运行。后台执行线程不能代替界面刷新心跳，避免界面卡死后后台继续完成整个档位。此机制已做离线检查，尚需在现场验证故障后的实际停转时间。

## 保护与统计

- 2026-10-18起不再设置固定的电流、功率、拉力中止门槛。不同电机和桨叶的允许范围不同，软件只记录读数，不断言硬件极限；过载保护由电调、电源、夹具和现场独立断电负责。
- 软件仍保留与硬件规格无关的安全检查：停止指令回执、输出回零、其他通道无输出、有限命令租约、相机画面不超过1秒、电压/电流/功率连续不可读不超过1.5秒、拉力连续不可读不超过2.5秒、界面心跳及执行进程存活。拉力允许更长间隔，是因为数码管刷新会让部分帧必然缺笔画；相机画面、采样序号和字段时效仍逐帧检查。
- 单档始终是预先声明的有界缓升与保持，不会根据读数自动追加更高档位。
- 新会话默认忽略目标档前2秒。新点统一使用同帧电压×电流计算输入功率，原始功率显示保留；不补零、不插值、不自动扣零。
- 单档结束后，任一关键量不足10个有效样本时，软件先记录本次失败尝试，再单独重测本档一次；仍不足才暂停后续档位，供人工复核。窗口可读率低于70%不触发重测，而是写入该档统计提示和报告：LED数码管刷新快于相机采样，部分帧必然会被正确拒读，有效样本数才是统计依据。CV进程现在会在每一帧单独扫描LED，发布样本的当前帧缺笔画时可沿用0.25秒内最近一次完整读数；沿用值来自真实完整帧，不拼接、不猜测，也不改变原稳定值判定。
- 自动重测只针对统计样本不足，且每次重测都是一次全新的有界缓升、保持和停机；不会因重测扩大档位、提高目标或跳过现场确认。重测前的失败尝试保存在独立 `stage_*_retry*` 目录，并在 `report.md` 的“自动重测记录”中列出，不计入曲线和 `results.csv`。若重测后仍不足，最后一个点会保留在记录中并标记统计不足，随后暂停方案，供人工复核。
- 历史灰线保留原始汇总口径，不能直接视为与新会话同条件。重复点单独显示，不替换或平均。
- 当前没有转速或温度传感器，软件不显示推测RPM或虚构温度，也不构成转速闭环。

## 记录与导出

每轮自动保存在`bench_app/runs/日期_编号/`：

- `session.json`：模式、测试对象、冻结方案、现场确认、状态及统计；
- `camera_config.json`及参考照片副本：实机会话使用的标定快照；
- `stage_*`：各档原始控制事件、逐帧识别、停止结果、实时预览和故障信息；
- `results.csv`、`report.md`、`curves.png`：本轮数据表、报告和曲线。

“导出本轮”保存汇总表、报告、会话索引和当前曲线图。完整原始日志保留在上述本地会话目录；需要交接原始数据时复制整个会话目录。

## 验证范围

本次开发验证使用离线故障测试、现有真实遥测的历史回放和桌面界面检查，没有启动电机。新界面的串口选择、预检和多档控制集成仍需在现场首次验收，不能把历史回放通过描述成新界面已经完成带桨实测。

开发检查：

```powershell
.\cv_mvp\.venv\Scripts\python.exe -m unittest bench_app.test_app
.\cv_mvp\.venv\Scripts\python.exe -m unittest bench_app.test_automatic
.\cv_mvp\.venv\Scripts\python.exe -m unittest discover -s px4_mvp -p test_hold.py
.\cv_mvp\.venv\Scripts\python.exe -m bench_app --smoke-test
```

`--smoke-test`使用隐藏窗口和历史数据，禁止创建硬件控制子进程。若在受限执行环境中提示找不到Tcl/Tk，需要让测试进程能够读取本机Python的Tcl/Tk运行库；不要通过关闭测试保护来解决。
