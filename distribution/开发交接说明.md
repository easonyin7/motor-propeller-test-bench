# 开发交接与重新打包说明

## 1. 工程结构与入口

| 目录 / 文件 | 职责 |
|---|---|
| `bench_app/app.py` | Tkinter中文界面、现场确认、监控、曲线、导出。 |
| `bench_app/model.py` | 档位范围、方案与时间、子进程命令。 |
| `bench_app/controller.py` | 任务编排、互斥、重测、续测、取消和会话状态。 |
| `bench_app/data.py` | 窗口统计、缺测处理、历史汇总、补点及导出。 |
| `px4_mvp/timed_hold.py`、`hold_core.py` | 有界输出、租约续期、基线、停止及数据健康检查。 |
| `px4_mvp/runtime_paths.py` | 先选包内runtime，原工程环境作为回退；控制与相机子进程均使用此逻辑。 |
| `cv_mvp/instrument_live.py`、`instrument_reader.py` | 相机采样、LCD/LED识别、局部定位、短时完整帧缓存。 |
| `runtime/` | 可离线使用的Python3.12与当前二进制依赖，不是原虚拟环境的直接复制。 |
| `distribution/` | 构建、自检、路径迁移、回归检查与交付文档。 |

双击 `Start_Bench.cmd` 或“启动上位机.cmd”；源码运行可在工程根目录执行 `runtime\python.exe -m bench_app`。直接运行模块前须先运行一次 `runtime\python.exe -I distribution\prepare_package.py`，以修正解压后的旧会话索引。

`python312._pth`把导入路径限制在包内；`sitecustomize.py`为包内Tcl/Tk定位，不依赖原电脑注册表、用户site-packages、Codex或Python安装目录。不要只移动runtime子目录。

## 2. 本次迁移修改

1. 解释器选择新增应用本地 `runtime/python.exe`，保留原CV虚拟环境的开发入口。
2. 控制进程启动相机时改为同一解释器选择方式，不再固定原虚拟环境位置。
3. 默认相机配置中的参考照片随包复制，改为包内相对路径。
4. 启动器在交付包首次启动、或解压目录改变后调用路径迁移工具，仅更新上位机会话索引及相机配置；保留原始遥测、CSV/JSONL、图片内容。
5. 发布包不附原机运行设置和未完成设备锁；启动默认历史回放。完整工程包保留测量数据，但不沿用原机临时运行缓存。

本次不修改油门流程、保持时间、原有过程门槛策略或统计判定。原MVP的辅助运行脚本可能仍优先寻找旧开发环境，交付主入口以上述启动器为准。

## 3. 历史数据与路径范围

完整工程包含原项目源码、备份、相机实验和实机日志；不包含原 `.venv`、`__pycache__`、临时文件、发布目录自身和上位机运行缓存。项目受保护的`sources/`若有内容只读复制，不修改。

首次启动迁移：`cv_mvp/instrument_config.json`、`bench_app/runs/*/session.json`、`bench_app/runs/*/camera_config.json`中指向原项目根目录的路径。原始控制日志里的构建机路径作为历史证据保留，旧的独立分析脚本、外部盘符引用不保证自动迁移。迁移后仍不应在更换测试对象或相机位置时直接续测旧会话。

历史回放使用 `integration_runs/campaign_summary_20261018/全档位数据_合并.csv`中的28条汇总及对应运行目录，不是任意会话播放器。新实机统计统一取目标保持窗口，默认去前2秒，功率由同帧V×I计算；拉力可能使用0.25秒内完整帧缓存。

## 4. 离线检查命令

在项目根目录执行，均不操作硬件：

```powershell
.\runtime\python.exe -m unittest bench_app.test_app distribution.test_distribution
.\runtime\python.exe -m unittest discover -s px4_mvp -p test_hold.py
.\runtime\python.exe -m unittest discover -s cv_mvp -p test_instrument_reader.py
.\runtime\python.exe -m bench_app --smoke-test
```

最后一项隐藏界面并回放历史数据，测试明确禁止创建硬件控制子进程。测试会生成自己的回放记录；不要把它们计为新测量。

## 5. 重新构建

构建器读取当前项目的基础Python、CV环境及 `px4_mvp/.deps`，复制真实依赖和许可，不依赖在线安装。使用Windows x64 Python3.12。

```powershell
.\runtime\python.exe .\distribution\build_release.py assemble --output .\releases\新的版本目录
```

原开发目录则使用 `cv_mvp\.venv\Scripts\python.exe`执行。输出目录须为新的空位置，不能复用已存在目录。执行离线回归、解压迁移和回放验证后，写入真实的交付验证记录，再生成清单及ZIP：

```powershell
.\runtime\python.exe .\distribution\build_release.py finalize --output .\releases\新的版本目录
```

构建在同一项目内使用 `releases/`输出，避免将输出再次打进完整工程。压缩包可使用ZIP64；交付后不要覆盖原始ZIP，再次更改应产生新版本和新SHA-256值。

## 6. 后续修改注意事项

- 不在界面线程发串口命令，不让后台线程代替界面刷新看护心跳。
- 软件ACK/输出回零与现场停转分开记录，不以回放或软件状态代签现场确认。
- 原始日志、失败尝试和重复点保留；统计不足重测不等于执行故障自动重启。
- 当前没有固定过载中止门槛、转速/温度传感器或拉力闭环，界面和文档应维持一致表述。
- 更改依赖、相机控制、固件、线程/进程、时间基准或停止机制后，需要对应回归和现场验收，不能只验证主界面能打开。

设备驱动和HIK IN需从设备供应方获取；不随本包附送，不修改系统驱动或注册表。
